# Пивоскан — дизайн приложения

Дата: 2026-11-03
Статус: на утверждении у заказчика

## 1. Зачем

Быстро ответить на вопрос «где в моём городе сейчас самое дешёвое пиво из того,
что я реально узнаю на полке». Пользователь не сравнивает десятки сайтов и не
листает акции: он открывает приложение, видит список предложений от дешёвого к
дорогому, фильтрует по сети и находит конкретную марку.

Приложение офлайн и демонстрационное: реальных API у сетей нет, поэтому цены
генерируются детерминированно из мок-базы. Это честно указано в интерфейсе.

Пользователь: русскоязычный покупатель 18+, телефон на Android 7.0+, чаще всего
смотрит приложение в магазине, одной рукой, в спешке.

## 2. Цели / не-цели

Цели:

- первый запуск → выбор города за 2 касания, выбор запоминается;
- главный экран отвечает «что дешевле» без прокрутки и без обучения;
- 7 городов × 4 сети × ≥30 предложений на город, цены зависят от города и сети;
- поиск по марке, фильтр по сетям, две сортировки;
- детали предложения + карта магазина + сравнение той же марки в других сетях;
- аккуратная светлая и тёмная тема, ни одного «дефолтного» экрана Material.

Не-цели:

- реальные цены, авторизация, карты, корзина, онлайн-оплата;
- сервер, сеть, аналитика, push;
- iOS, планшеты как отдельный сценарий (layout тянется, но не оптимизируется);
- добавление городов/товаров пользователем.

Анти-цели (считаем провалом, даже если код работает):

- «таблица» из одинаковых серых строк без визуальной иерархии;
- пустой экран при первом запуске или мигание выбора города при повторном;
- цены одинаковые во всех городах и сетях;
- тёмная тема как инверсия светлой (грязные акценты, нечитаемый текст);
- приложение требует интернет или падает без него.

## 3. Ограничения

- Только офлайн, без `INTERNET` в манифесте.
- minSdk 24, targetSdk 35, compileSdk 35, Kotlin, AGP 8.7, Gradle 8.9, JDK 17.
- Один модуль `app`, классические Views + XML + ViewBinding (заказчик просил
  MainActivity/адаптеры/разметку), без Compose.
- Зависимости: `androidx.core:core-ktx`, `appcompat`, `material`, `constraintlayout`,
  `recyclerview`, `core-splashscreen`. Всё остальное — руками, без лишних библиотек.
- Язык интерфейса — русский, строки только в `strings.xml`.
- APK собирается здесь и отдаётся файлом; исходники — рядом архивом.

## 4. Рассмотренные подходы

**A. Нативные Views + XML + Material 3 — выбран.**
Плюсы: ровно то, что просил заказчик (MainActivity, адаптеры, XML), предсказуемая
вёрстка, малый APK (~2 МБ), быстрый запуск на слабых телефонах, легко править без
Compose-знаний. Минусы: анимации и сложные состояния пишутся вручную, кода чуть
больше, чем в Compose.

**B. Jetpack Compose.**
Плюсы: короче UI-код, удобные состояния и анимации. Минусы: просили XML/адаптеры,
APK тяжелее, для правок заказчику нужен Compose-опыт, риск «типового» Material 3
экрана выше, если не рисовать всё самому.

**C. HTML/JS в Capacitor или Cordova.**
Плюсы: быстрый дизайн, один код на всё. Минусы: WebView-прокрутка и ввод ощущаются
чужими, APK тяжелее, всё равно нужен Android SDK, офлайн-шрифты и тема сложнее,
нативные детали (bottom sheet, ripple, статус-бар) имитируются.

Решение заказчика: **A**.

## 5. Экраны и сценарии

### 5.1 Выбор города (`CityPickerActivity`, launcher)

- Тёмный/светлый фон с мягким янтарным градиентом, edge-to-edge.
- Кастомная иллюстрация: стилизованный стакан пива, нарисованный на Canvas,
  с анимацией наполнения при старте (1.1 с, один раз). Не картинка-заглушка.
- Надзаголовок «ПИВОСКАН» (letterspaced), заголовок «Где сегодня дешевле?»,
  подзаголовок «Сравниваем цены в Магните, Дикси, Пятёрочке и Fix Price».
- Выпадающий список городов (Material exposed dropdown): Москва, Санкт-Петербург,
  Краснодар, Екатеринбург, Новосибирск, Казань, Нижний Новгород. По умолчанию
  ничего не выбрано — кнопка неактивна.
- CTA «Найти пиво» (56 dp, радиус 16). По нажатию: сохранение города, переход в
  главный экран, `finish()`.
- Сноска «Демо-данные · работает без интернета».
- Если город уже сохранён — экран сразу перекидывает в `MainActivity` (splash
  держится до решения, без мигания).

### 5.2 Главный экран (`MainActivity`)

Сверху вниз, всё кроме списка — фиксировано:

1. TopAppBar: иконка геометки + название города (title), действие «Сменить»
   (текстовая кнопка), overflow: «Тема» (Системная/Светлая/Тёмная) и «О данных».
2. Поиск: `TextInputLayout` outlined, радиус 16, иконка лупы, кнопка очистки,
   placeholder «Марка пива, например, Жигули». Фильтрация с задержкой 180 мс.
3. Чипы сетей в горизонтальном скролле: «Все», «Магнит», «Дикси», «Пятёрочка»,
   «Fix Price». Мультивыбор: «Все» сбрасывает остальные; выбор сети снимает «Все»;
   нажатие на выбранную сеть при пустом остальном возвращает «Все».
4. Строка результата: «34 предложения · от 59 ₽» слева, справа сегмент-переключатель
   «Дешевле» / «Скидки». «Дешевле» — по умолчанию.
   Сортировка «Скидки»: сначала больший процент скидки, затем цена.
5. Список карточек (RecyclerView, LinearLayoutManager). Появление: fade+slide
   8 dp, шаг 24 мс, не больше 6 элементов.

Карточка (`item_beer.xml`):

```
● МАГНИТ                                    −27%
Жигули Барное
0,5 л · стекло
71 ₽   ~~97 ₽~~                    экономия 26 ₽
```

- Цветная точка сети + её название капсом 11 sp, letterSpacing 0.08.
- Бейдж скидки справа, янтарный контейнер.
- Название 17 sp semibold, до 2 строк.
- Объём и тара 13 sp, вторичный цвет.
- Цена 24 sp bold; старая 13 sp зачёркнутая; «экономия N ₽» зелёным 12 sp.
- Если это минимальная цена на эту марку среди отфильтрованных — зелёный бейдж
  «минимум» вместо/рядом с экономией. Ключевая фича: сразу видно победителя.
- Карточка: радиус 20, без тени, тонкая обводка (светлая тема) / surface (тёмная),
  ripple, весь блок кликабелен.

Состояния:

- пусто → иллюстрация стакана (line-art), «Ничего не нашлось», подсказка,
  «Сбросить фильтры»;
- смена города → возврат на главный с сохранённым выбором, фильтры сбрасываются;
- поворот экрана → фильтры, поиск и позиция списка сохраняются.

### 5.3 Детали товара (`BeerDetailsActivity`)

Отдельный экран (не bottom sheet: карте нужно место), вход — slide-in справа,
выход — назад/свайп системного жеста. Внутри вертикальный скролл:

1. Шапка: точка сети + название сети, крупно марка (26 sp), объём и тара.
2. Цена 34 sp, старая зачёркнутая, бейдж «−27%», «Экономия 26 ₽» зелёным.
3. **Карта** (см. 5.4): карточка 220 dp, радиус 20, схема города с меткой сети,
   поверх снизу — плашка с адресом. Тап по карте = «Открыть в картах».
4. Кнопка «Открыть в картах» (outlined, 52 dp, иконка навигации) + вторичная
   текстовая «Скопировать адрес» (Clipboard, тост «Адрес скопирован»).
5. Блок «Адрес и часы»: адрес, «ежедневно 08:00–23:00», подпись «Демо-адрес».
6. Блок «В других магазинах»: та же марка в этом городе, по возрастанию цены;
   текущая сеть подсвечена, у самой дешёвой — зелёный бейдж «дешевле всего».
   Если предложение одно — блок скрыт.
7. Плашка «Цены демонстрационные и не являются офертой».

### 5.4 Карта

Реального API карт нет (нет ключа, нет интернета), адреса — мок-данные, поэтому
внутри приложения карта **схематичная и офлайн**, нарисованная на Canvas:

- `CityMapView` рисует по сиду «город + сеть»: изгиб реки, парк, сетку улиц под
  небольшим углом, кварталы, пару подписей улиц, точку метро и метку магазина
  (кружок цвета сети + белая булавка + подпись сети).
- Две палитры: светлая («бумажная»: кремовые кварталы, белые дороги, бледно-зелёный
  парк, голубая река) и тёмная (графитовые кварталы, дороги чуть светлее фона,
  тёмно-зелёный парк, тёмно-синяя река).
- Лёгкая анимация появления метки (scale 0.8→1 + fade) при открытии экрана.
- Нажатие на карту или кнопка «Открыть в картах» → `geo:0,0?q=<адрес, город, сеть>`
  через `ACTION_VIEW`; если обработчика нет — `https://yandex.ru/maps/?text=<...>`
  в браузере. Разрешение `INTERNET` приложению не нужно: сеть использует само
  приложение карт.
- Если пользователь отклонил выбор приложения — показываем снекбар
  «Не нашлось приложения карт».

### 5.5 Тема

- По умолчанию `MODE_NIGHT_FOLLOW_SYSTEM`; ручной выбор сохраняется в prefs.
- Смена темы применяется без перезапуска (`AppCompatDelegate` + `recreate`).
- Статус-бар и навигация — edge-to-edge, иконки подстраиваются под тему.

## 6. Визуальное направление

Не «ещё один Material-шаблон». Настроение: тёмный бар, янтарное стекло, тёплая
бумага в светлой теме. Акцент — пивное золото, второй акцент — зелёный «выгода».
Никаких фиолетовых градиентов, стоковых иконок пива и теней на всё.

чипы 36, иконки 20–24. Тап-зоны не меньше 48 dp.

**Движение:** наполнение стакана на онбординге, fade+slide карточек, ripple,
animated bottom sheet. Без параллаксов и «прыгающих» элементов.

## 7. Данные

### 7.1 Модели

```kotlin
City(id, name, priceIndex, streets: List<String>)
Store(id, name, shortName, color)
Beer(id, brand, title, volumeMl, package, basePrice)
Offer(id, beer, store, cityId, price, oldPrice?, discountPercent, address, hours)
```

### 7.2 Каталог

- 20 марок: Жигули Барное/Разливное, Балтика 3/7/9, Амстел Классик/Фреш, Хайнекен,
  Козёл Тёмный/Светлый, Кроненбург 1664/1664 Блан, Эсса, Хугарден, Белый Медведь,
  Охота Крепкое, Жатецкий Гусь, Старопрамен, Бочкарёв, Хамовники.
- Базовая цена 62–139 ₽, объём 0,33/0,45/0,5 л, тара стекло/банка.
- Матрица наличия: Магнит, Дикси, Пятёрочка — почти всё; Fix Price — только
  Жигули, Балтика 3, Охота, Белый Медведь, Бочкарёв. Итог ~48–56 предложений на
  город (требование ≥30 выполнено с запасом).

### 7.3 Генерация цен (детерминированная)

```
seed    = FNV-1a(cityId + storeId + beerId)
jitter  = 0.94 + (seed % 15) / 100        // 0.94…1.08
price   = round(basePrice * cityIndex * storeIndex * jitter)
discount= if (seed % 10 < 4) 5 * (5 + seed % 5) else 0   // 25…45 %
oldPrice= if (discount > 0) round(price / (1 - discount/100)) else null
address = city.streets[seed % size] + ", " + (1 + seed % 120)
```

`cityIndex`: Москва 1.12, СПб 1.06, Екатеринбург 0.98, Казань 0.96, Новосибирск
0.95, Н. Новгород 0.94, Краснодар 0.93.
`storeIndex`: Магнит 0.97, Дикси 1.02, Пятёрочка 1.00, Fix Price 0.86.

Свойства: одинаковые данные при каждом запуске и на любом устройстве; цены
различаются по городам и сетям; Fix Price системно дешевле, Москва дороже.

### 7.4 Фильтрация

Единая функция `query(city, stores, text, sort)` → `List<Offer>`; поиск — по
нормализованной строке (lowercase, `ё→е`, без лишних пробелов), по названию и
бренду. «Минимум» считается по результату фильтра до сортировки.

## 9. Проверка

1. `./gradlew :app:assembleRelease` проходит без ошибок, `lintRelease` — без
   критичных замечаний.
2. JVM-тесты `PriceEngine`: ≥30 предложений в каждом городе, цены > 0, скидки
   корректны, `oldPrice > price`, поиск находит «жигули» и «ЖИГУЛИ», фильтр по
   сети работает, сортировки упорядочены, генерация стабильна между вызовами.
3. `apksigner verify` + `aapt2 dump badging` (package, minSdk 24, нет INTERNET).
4. Карта: экран деталей открывается, схема рисуется в обеих темах, тап по карте
   и кнопка вызывают `geo:`-интент (проверяем через `adb shell am start` на
   эмуляторе/`cmd package resolve-activity`), фолбэк на веб-карты не падает.
5. Если на машине доступна аппаратная виртуализация — эмулятор API 35, скриншоты
   обоих экранов и карты в светлой и тёмной теме, проверка онбординга и повторного
   запуска. Если виртуализации нет — проверка сборки/линта/тестов и ручной
   чек-лист для заказчика.
