# Пивоскан 1.4.3-test: восстановление кеша при запуске

Основа ed307b4 (1.4.2-test), versionCode новой сборки 8.

## Доказательства

Отчёт пользователя с Android 15 / 1.4.2-test содержит NullPointerException:
Offer.copy → CityScanSnapshot.getOffers → asLegacySnapshot → MainActivity.render.
Падение происходит при подготовке сохранённых предложений к показу.
Сообщения исключений в диагностике исключены, поэтому имя конкретного null-поля
на телефоне в отчёте отсутствует.

Регрессии воспроизвели эту же цепочку: legacy schema 1 без priceEvidence
падает в Offer.copy на priceEvidence; запись с null hours — на hours.
Gson создаёт объект в обход Kotlin-конструктора и его значений по умолчанию.
Миграция v1 не восстанавливала priceEvidence, а валидатор пропускал эти null.
Нормализация v2 до исправления покрывала только отсутствующее/null evidence,
но не hours и не неизвестное строковое значение enum.

## Исправление

Общий CachedOfferDefaults применяется перед десериализацией в трёх путях:
LegacyCatalogMigration, CityScanCodec и совместимый SnapshotCodec.
Отсутствующий/null/неизвестный priceEvidence становится UNKNOWN;
отсутствующие необязательные hours, brand, packageName становятся пустыми строками.
Известные CONFIRMED и CONDITIONAL сохраняются. Цены, адреса и даты не изменяются.
Граница записи дополнительно отвергает null в обязательных полях объектов,
которые Gson может создать в обход Kotlin-проверок.

Не требуется очистка данных приложения. Все возможности 1.4.2 сохранены.
Исходный пользовательский отчёт и идентификаторы запусков в Git не добавлены.

## Проверки

Регрессии проверяют восстановление v1 и v2, немедленное построение списка,
сохранность цены/даты, исторический статус, отсутствие ложного минимума,
сохранение известного статуса цены и последующее добавление второго магазина.
Падение до исправления зафиксировано в startup-cache-red.log.
Итоговые результаты сборки и тестов записаны в startup-cache-final.log
(локальная папка .superpowers/sdd/2026-11-04-citywide-catalog).
