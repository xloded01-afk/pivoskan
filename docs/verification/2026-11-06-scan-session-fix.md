# 1.4.1 — автозапуск по открытию приложения

Пользователь подтвердил: Home/возврат продолжают тот же обход без сброса;
после полного закрытия (удаления задачи из недавних) и нового открытия нужен новый обход.
Ручное обновление и смена города остаются явными причинами нового обхода.

Причина слабой защиты 1.4: started хранится только в памяти процесса,
visibilityChanged запускает обход после восстановления процесса. Это смешивает
восстановление существующей задачи и новое открытие.

Изменения: AutoScanSession сохраняет taskId+город, привязанные к boot count.
Повторные callbacks резервируют один запуск до старта сервиса; отказ запуска допускает повтор.
MainActivity передаёт taskId при открытии/возврате. Видимость теперь только регулирует доступ,
не инициирует обход. Новый task запускает замену даже при живом процессе/старом сервисе.
Декодирование кеша переводит WAITING/RUNNING в PARTIAL, поскольку прежнего процесса уже нет.

JVM: возврат/поворот/дубликаты, восстановление процесса, новое окно при живом процессе,
смена города, ручное обновление, отказ сервиса, отсутствие фантомного RUNNING из кеша.

Проверки Android пока не выполнены:
- [ ] Home → возврат: счётчик не сбрасывается.
- [ ] Экран блокировки → возврат: тот же обход.
- [ ] Завершение → Home → возврат: новый обход не начинается.
- [ ] Отмена → Home → возврат: отмена сохраняется.
- [ ] Поворот и открытие уведомления: без дубликатов.
- [ ] Удаление из недавних → новое открытие: новый обход.
- [ ] Убийство процесса системой с сохранением задачи → возврат: кеш, без нового обхода.
- [ ] Кнопка «Обновить» и смена города запускают новый обход.
